# Design

## Context

See `proposal.md` for why. Today `ConsoleCore`'s `HostClient` hand-builds every request in one
`send` over a `HostTransport` seam (`URLSessionTransport` in the app, `FakeTransport` in tests), with
calls for the version, `/v1/host`, pairing and clients. `HostConnection` owns it, the `TokenStore`,
and the `HostPairing` and `PairedClients` models the connect window's sheets show.
`APIVersion.supportedMajor` is a constant. The panel window is `SketchShell`, shown only in Debug
builds, over `SketchData`.

The host's contract (`make openapi` in `../audio-vue` writes `local/openapi.json`) is OpenAPI 3.1. It
declares an `HTTPBearer` scheme and puts `security` on every operation that takes the token, and none
on the version and the two pairing routes. `/v1/events` is described only in the contract's
description: each message is one whole `State`, the first on connect, then on change and in whole
every second; the handshake takes `Authorization: Bearer`, and a refused one is closed with 1008.

Constraints: `ConsoleCore` imports no UI framework and the app target does no networking
(`app-boundaries`); the quality gate checks every edited Swift file, with warnings as errors.

## Goals / Non-Goals

**Goals:**

- One generated client, fed by one saved contract, so a host change reaches the app by refreshing a
  file.
- The token and `Origin` rules applied once, for routes not yet called as much as for those that are.
- What the Overview shows decided in `ConsoleCore`, where Swift Testing reaches it.

**Non-Goals:**

- More than one panel at a time, discovery, or the picker listing several panels.
- Building any sidebar page but Overview, or any command (switch, reload, start, stop).
- Calling the software-update routes. They are generated with the rest and left unused.

## Decisions

### D1. Apple's swift-openapi-generator, as a build plugin

The client is generated by `swift-openapi-generator`'s build plugin, with `swift-openapi-runtime`
and `swift-openapi-urlsession`, pinned by exact version in `Package.swift`.

- *Over committing generated code*: committed output would sit in the source tree as files the gate
  checks, past the 300-line file limit at once, and every refresh would be a large diff of no one's
  writing. A build plugin's output lives in the build directory.
- *Over a hand-written Codable client*: 40 routes and 59 schemas, changing as audio-vue changes, kept
  in step by hand.
- The generator is set to generate types and the client, with idiomatic naming, internal access.

### D2. A `HostAPI` target holds the contract and the generated code

`ConsoleCore` gains an internal target, `HostAPI`, holding `openapi.json`, the generator's config and
nothing else; `ConsoleCore` depends on it, and no product exports it, so the app cannot import it.
The generated types never cross `ConsoleCore`'s public surface: `HostClient` stays its face, turning
generated answers into `ConsoleCore`'s own values (`HostVersion`, `HostIdentity`, `PanelState`,
`PairedClient`) and failures into `HostFailure`. The generated `Client` is bound to one server URL,
and `HostClient` takes an address per call, so each call builds a `Client` for its address and token;
building one is cheap and holds no connection of its own.

- *Over generating into `ConsoleCore` itself*: the generated names would mix with the core's own,
  and the app could reach them.
- *Over exposing generated types to the app*: every refresh would ripple into views. Behind the face,
  a refresh changes `ConsoleCore` at most.
- `HostAPI` keeps warnings as errors. If the generated code warns under Swift 6, that is raised with
  the maintainer before any setting changes (`.claude/CLAUDE.md`, "Quality Gate").

### D3. The saved contract is read at run time for the version and the open routes

`openapi.json` is also a resource of `HostAPI`. A `SavedContract` value reads it once: the major
version from `info.version`, and the set of operation ids with no `security`. `APIVersion`'s
compatibility is measured against `SavedContract`'s major, and `supportedMajor` goes.

- *Over a constant checked by a test*: a refresh would need a code edit, and the spec says the
  contract is the only record.
- A contract that will not read is a build defect, not a host's: the read throws no `try?`, and a
  test fails if the bundled contract does not give a major and at least the three open routes.

### D4. One middleware applies the host's rules

A `HostRules` `ClientMiddleware`, made with the call's token, removes any `Origin` header and adds
`Authorization: Bearer` to every operation not in `SavedContract`'s open set. `HostClient`'s calls
keep their `token:` argument, as today, and hand it to the `Client` they build; the per-route code
never touches a header. A 401 on a call that carried a token is `HostFailure.tokenRefused`, decided
once in `HostClient` for all calls.

- *Over reading the token from the `TokenStore` in the middleware*: `HostPairing.confirm` reads
  `/v1/host` with the new token before it is saved, since the store is keyed by the host id that read
  gives (alignment F1).
- *Over listing the open routes*: the contract already says which they are.

### D5. `HostTransport` goes, and tests fake the runtime's transport

`HostTransport` and `URLSessionTransport` are replaced by the runtime's `ClientTransport` and the
`swift-openapi-urlsession` transport, set up as today: ephemeral session, no cache, five seconds.
`FakeTransport` becomes a `ClientTransport` that answers by method and path, as it does now, and
records each request, so the existing client, pairing and clients tests keep their shape. A transport error is unwrapped from
the runtime's `ClientError` to tell an unanswered host from a bad answer, as `HostClient.unanswered`
does now.

### D6. `/v1/events` is a hand-written socket owned by `LiveState`

`LiveState`, `@Observable` and `@MainActor` in `ConsoleCore`, holds the newest `PanelState`, whether
it is live, and runs the socket through an `EventSource` seam: `URLSessionWebSocketTask` in the app,
a scripted fake in tests. The handshake request is built by the same rules as D4. Each message is
decoded as the generated `State` and turned into a `PanelState`.

- **Lifetime.** The panel window starts `LiveState.watch()` in a `.task`, so the socket is open while
  the window shows a paired host and closes when it closes, when the host changes, or when the token
  is forgotten. The connection outlives the window; the stream does not need to.
- **Closing.** On a close or error, the state is kept and marked not live, and the socket is opened
  again after 1 s, doubling to at most 30 s, back to 1 s after a message arrives.
- **Silence.** The socket's session keeps the five-second request timeout. The host pushes the whole
  state every second, so five seconds with no message is treated as a close.
- **Revoked elsewhere.** The host does not close an open socket when its client is revoked
  (audio-vue's `events` loop checks the token only at the handshake), so the stream runs on until the
  next close; the next request or reopening finds the token refused.
- **Refusal.** A refused handshake cannot be told from an `Origin` refusal (both 1008), so it is
  followed by `GET /v1/host` with the token. A 401 there forgets the token, as `host-pairing` says,
  and stops the loop; anything else retries as a close.

### D7. The Overview's rows are decided in `ConsoleCore`

`OverviewRows`, a pure function of the connection's state, `HostIdentity` and `PanelState`, gives
each section's labelled values as text, `—` for every nil, every value not read, and everything while
not paired. The view only lays them out. Formatting:

- The condition as words: `Up`, `Down since <time>` (the state's `since`), `Not drawing` for `stale`,
  which audio-vue means as drawing stopped and not measuring stopped, `Capture stopped`, `No audio`.
- The rate in kHz; analysis as the p99 time of the budget; the display as `W × H`, and its shape as
  the ratio reduced by their greatest common divisor (`16:9`, `8:3`).
- Calibration's status as words for the values audio-vue gives today (`calibrated`, `stale`,
  `shifted_by_hand`, `obsolete`, `uncalibrated`), and as the host's text for any other, since the
  contract types it as a plain string. Age in days.
- A section the host reports as `{"unavailable": "<reason>"}` (audio-vue `control-state`, "A section
  that fails is contained") shows `—` for its values and the reason under the section.

- *Over formatting in the view*: the dash rule is the spec's, and only `ConsoleCore` is under test.

### D8. The window

`SketchShell` becomes `PanelWindow` and `SketchOverviewPage` becomes `OverviewPage`, both out of
`Sketches/` and out of `#if DEBUG`, in a single `Window` scene that replaces "Host Connection".
`SceneStore` and `ArrangeCommands` leave `#if DEBUG` with it, since Scenes is now in every build.

- The picker shows the one panel from `HostConnection`; Add Panel… opens a sheet with today's address
  field, status and Connect, and a connect there replaces the held panel. The connect at launch moves
  from `ConnectView`'s `.task` to `PanelWindow`'s.
- `ConnectionStatus` and `PairingSection` (in `ConnectView.swift`) and `ClientsForm` (in
  `ClientsSheet.swift`) move to files of their own before those files go, for the sheet and the
  Pairing section to use. `PairingSheet` stays a sheet. `ConnectView`, `ClientsSheet` and
  `HostCommands` go.
- `HostConnection` gains `host: HostIdentity?`, kept from the `/v1/host` read it already makes to
  learn whether it is paired, and makes `LiveState` and `PairedClients` for the window; `showClients()`
  and the `clients` sheet item go, since the list is always shown when paired.
- `SketchSection.access` goes. The other pages take `SketchData`'s first sample panel, since the picker
  no longer holds a `SketchPanel`.

### D9. Refreshing the contract

`tools/refresh-contract.sh` runs `make openapi` in `../audio-vue` and copies `local/openapi.json` over
`ConsoleCore/Sources/HostAPI/openapi.json`; with `--check` it copies nothing and exits non-zero on a
difference, printing it. `commands.md` records both. This is the check `.claude/CLAUDE.md`'s "Host
Versions" runs at the start of project work.

## Risks / Trade-offs

- [The generated code warns, or fails Swift 6's strict concurrency, under warnings as errors] → The
  first task generates from the saved contract and builds with `swift build` and Xcode before
  anything else is moved; any warning goes to the maintainer (D2).
- [Xcode asks to trust the generator's build plugin, and `xcodebuild` refuses an untrusted one] → The
  maintainer enables it once in Xcode, a plain next step; `swift build` and `swift test` need nothing.
- [The plugin may not see `openapi.json` once it is also declared a resource] → Checked in the first
  task. If it cannot be both, the refresh script also writes the two facts D3 reads into a small
  generated file beside it, still never edited by hand.
- [`URLSessionWebSocketTask` might add an `Origin` header to the handshake] → Checked against the
  proving host in the first socket task. A refusal from it would show as a refused handshake with a
  token the host still takes, which D6 retries rather than forgetting the token.
- [OpenAPI 3.1's `anyOf` with `null`, used for every nullable field, might not come out as optionals]
  → Seen in the first task's generated types; a field that does not is handled at the face (D2).
- [The socket's 4 Hz poll on the host while the window is open] → The host's poller costs the panel
  nothing (audio-vue `control-state`: capture, analysis and drawing never wait on a client), and the
  socket closes with the window.

## Open Questions

- Whether analysis is better shown at p50 or p99 against its budget. p99 for now; a one-line change
  in `OverviewRows`.
- How an odd display size reads as a shape (1366 × 768 reduces to 683:384). Rare on a panel; left as
  the reduced ratio.
